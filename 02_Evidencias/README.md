# Entregables y evidencias por actividad

Esta carpeta permite localizar los productos esperados de las actividades del proyecto **PJtra001 — Conecta Joven: oportunidades para el empleo** y consultar sus respectivos Issues de GitHub.

La matriz es un instrumento de seguimiento: registrar un entregable como esperado no significa que ya esté elaborado, entregado o verificado. El estado debe actualizarse únicamente cuando exista información suficiente para respaldarlo.

> **Nota sobre el ejercicio académico:** San Gabriel es un municipio ficticio. Las actividades, registros o resultados simulados deben identificarse expresamente como simulados y no presentarse como hechos reales.

## 2. ¿Qué debe guardarse como evidencia?

Conserva el archivo o soporte que permita verificar el trabajo realizado. Según la actividad, puede tratarse de:

- **ACT-01:** mapa de aliados y registro de acercamientos o acuerdos.
- **ACT-02:** protocolo de atención con versión identificable y registro de revisión.
- **ACT-03:** formatos, instrumentos y matriz de indicadores.
- **ACT-04:** piezas de convocatoria y registro de difusión o inscripción.
- **ACT-05:** instrumento y registros de caracterización y asignación.
- **ACT-06:** registros de servicios de orientación prestados.
- **ACT-07:** plan o materiales formativos y registros de participación o evaluación.
- **ACT-08:** registro de oportunidades, fuentes consultadas y encuentros.
- **ACT-09:** registro de postulaciones, remisiones y seguimiento.
- **ACT-10:** reportes de avance, registro de riesgos, decisiones y ajustes.
- **ACT-11:** informe de evaluación, resultados documentados y recomendaciones.

Esta lista es orientativa: guarda solo soportes pertinentes que efectivamente existan y estén autorizados para compartirse.

## 3. Organización recomendada de los archivos

Para facilitar la consulta, se propone organizar las evidencias por código de actividad:

```text
02_Evidencias/
├── README.md
├── ACT-01/
├── ACT-02/
├── ACT-03/
├── ACT-04/
├── ACT-05/
├── ACT-06/
├── ACT-07/
├── ACT-08/
├── ACT-09/
├── ACT-10/
└── ACT-11/
```

Esta es una **estructura recomendada**, no una descripción de carpetas que ya estén creadas. Crea cada carpeta cuando vayas a incorporar un soporte real; evita agregar archivos vacíos o evidencias inventadas.

Cuando sea pertinente, usa nombres de archivo consistentes, por ejemplo: `ACT-03_Matriz-indicadores_v1_2026-10-27.xlsx`. Ajusta el tipo de archivo y la fecha a la evidencia real, y no uses fechas o versiones ficticias.

## 4. Criterios para validar una evidencia

Antes de marcar un entregable como verificado, comprueba que:

- [ ] Corresponde a la actividad y al entregable esperado.
- [ ] El archivo está disponible y se puede abrir.
- [ ] Tiene nombre claro y, cuando corresponda, fecha y versión.
- [ ] Permite comprobar el producto o la gestión descrita.
- [ ] Está vinculado desde el Issue correspondiente.
- [ ] Las limitaciones o pendientes están documentados.
- [ ] Los datos simulados están identificados como tales.
- [ ] No expone datos personales identificables ni información reservada.

El estado del Issue, por sí solo, no demuestra que el entregable exista o haya sido verificado.

## 5. Protección de datos

Este repositorio es público. No publiques fichas con nombres, documentos de identidad, datos de contacto, información sensible ni registros individualizados de participantes. Usa versiones anonimizadas o agregadas cuando sean suficientes para demostrar el trabajo. Los documentos reservados deben mantenerse en un espacio autorizado con controles de acceso adecuados; el Issue puede incluir una referencia no sensible si es necesario dejar trazabilidad.
